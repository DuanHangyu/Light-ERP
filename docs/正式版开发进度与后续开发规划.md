# 轻量级定制生产流转 ERP 正式版开发进度与后续开发规划

文档版本：v1.0  
更新日期：2026-05-14  
适用范围：第一期功能确认版至正式上线版开发管理  
项目定位：本地私有化部署的轻量级定制 ERP，围绕销售订单主线，串联销售、商务内勤、采购、仓库、生产、质检、财务、管理层与系统管理员。

## 1. 文档目的

本文档用于记录当前系统已经完成的正式版能力、尚未完成的关键差距、后续开发优先级和验收建议。

该文档不是对外报价文件，也不是客户最终验收报告，而是项目内部开发进度台账。后续每完成一个正式模块，建议同步更新本文档，避免功能越来越多后出现范围失控、重复开发或验收口径不清的问题。

## 2. 当前总体进度判断

当前系统已经从早期演示原型升级为具备真实数据库、真实业务流转、真实单据状态、真实库存与账款联动能力的第一期正式功能确认版。

从客户采购评审和现场演示角度看，系统已经具备较强说服力；从长期正式上线运行角度看，还需要继续补齐配置化、权限精细化、数据初始化、异常处理、运维部署和正式验收文档。

| 维度 | 当前状态 | 进度判断 |
| --- | --- | --- |
| 第一阶段功能确认版 | 已具备完整演示和核心闭环 | 约 80% |
| 正式试点上线版 | 业务闭环基本具备，仍需强化配置和真实数据导入 | 约 65% |
| 长期生产正式版 | 仍需补齐部署、权限、配置、审计、异常与运维体系 | 约 55% |

当前不是简单静态 Demo。系统已经使用本地 SQLite 数据库、真实服务端动作、数据库迁移、审计日志、附件归档、打印预览和测试用例，具备继续升级为正式交付系统的基础。

## 3. 当前技术基线

| 项目 | 当前方案 |
| --- | --- |
| 前端框架 | Next.js App Router + TypeScript |
| UI | 单页 ERP 工作台，多模块左侧导航，商用管理软件风格 |
| 数据库 | SQLite 本地数据库，支持迁移扩展 |

## 5. 当前已知差距

### 5.1 配置化不足

当前很多规则已经具备逻辑，但部分仍为演示内置或半配置状态。

需要继续配置化的内容：

- 供应商必备资质规则。
- 供应商评分模型。
- 供应商等级规则。
- 采购审批阈值。
- 质量异常原因字典。
- 收率预警规则。
- 单据编号规则。
- 打印模板抬头和页脚。

### 5.2 权限仍需精细化

当前是动作级 RBAC 和预置账号，已经足够演示和第一期确认。但正式上线需要：

- 用户管理页面。
- 角色管理页面。
- 权限矩阵配置。
- 数据范围权限。
- 导出权限控制。
- 敏感成本字段权限。
- 配方算价保密权限。

### 5.3 真实数据导入仍需强化

已经具备主数据和期初数据导入基础，但正式上线前需要：

- 客户真实 Excel 模板确认。
- 数据清洗规则。
- 导入前校验报告。
- 导入失败原因明细。
- 导入批次回滚。
- 编码重复处理。

### 5.4 单据模板仍需客户信息

客户尚未提供：

- 公司名称。
- Logo。
- 税号。
- 地址。
- 电话。
- 开户行。
- 正式单据编号规则。
- 单据页脚。
- 合同条款。

当前可以继续开发通用模板，但最终正式单据需要客户提供这些资料后再定稿。

### 5.5 部署与运维还需正式化

当前具备本地数据目录、备份和恢复基础。正式上线还需要：

- Windows 或 Linux 服务器部署方案。
- 局域网访问配置。
- VPN 或远程访问方案。
- 定时备份计划。
- 备份校验机制。
- 恢复演练流程。
- 日志清理策略。
- 数据库维护说明。

## 6. 后续开发建议路线

### 阶段 A：供应商和采购风险控制收口

优先级：P0  
目标：把供应商准入、资质、采购特例放行做成完整正式模块。

建议开发内容：

1. 供应商资质要求配置页面。
2. 资质缺失自动生成整改任务。
3. 特采放行审批。
4. 特采放行有效期和次数限制。
5. 特采下单审计和报表。
6. 供应商评分模型配置。

理由：

当前已经完成资质矩阵和下单拦截，下一步最自然的是允许管理员配置规则，并允许特殊情况下经管理层审批后临时放行。这样采购系统既严格又符合真实业务弹性。

### 阶段 B：正式权限与用户管理

优先级：P0  
目标：从预置账号升级到客户可维护的用户和权限体系。

建议开发内容：

1. 用户新增、停用、重置密码。
2. 角色管理。
3. 权限矩阵页面。
4. 敏感字段权限。
5. 导出权限。
6. 登录日志。
7. 操作审计查询。

理由：

客户正式上线时一定会涉及多人使用，权限体系是正式版可信度的重要部分。

### 阶段 C：正式数据初始化工具

优先级：P0  
目标：让客户真实资料能安全导入系统。

建议开发内容：

没有可靠的数据导入，系统难以进入真实试点。

目标：让财务导出和对账更接近真实工作。

## 7. 下一步最建议开发的功能

建议下一步直接开发：

## 供应商资质要求配置页面 + 资质缺失整改闭环 + 特采放行审批

具体拆解：

1. 系统管理员维护“必备资质要求”：
   - 适用范围：全部供应商、指定物料、指定物料类别。
   - 资质类型。
   - 资质名称。
   - 最小有效天数。
   - 是否阻止下单。
   - 是否允许特采审批。

2. 系统自动生成缺失资质整改任务：
   - 缺证。
   - 过期。
   - 临期。
   - 未上传附件。

3. 采购员发起特采放行：
   - 选择供应商。
   - 选择采购物料。
   - 填写原因。
   - 上传供应商承诺或补证计划。

4. 管理层审批特采：
   - 同意后允许指定供应商、指定物料、指定时间内下单。
   - 驳回后继续拦截。

5. 特采审计和报表：
   - 特采次数。
   - 特采供应商。
   - 特采金额。
   - 特采到期。
   - 后续补证完成情况。

该功能能把当前“硬拦截”升级为“正式风控流程”，更符合真实企业采购场景。

## 9. 当前结论

当前系统已经具备正式版第一期功能确认的基础能力，客户可以通过现有系统看到从订单、采购、生产、仓库、质检、财务到供应商风控的完整业务主线。

接下来开发重点不应再盲目扩大模块数量，而应围绕正式上线需要，把已有模块做配置化、精细化、可验收化：

- 规则可配置。
- 数据可导入。
- 权限可管理。
- 单据可定稿。
- 异常可闭环。
- 部署可交付。

只要继续按这个方向推进，项目可以从当前功能确认版稳定升级到客户可试点运行的正式版本。
