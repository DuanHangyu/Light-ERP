# ERP 平行账套详细场景操作指南

> 适用系统：Local ERP 正式账套  
> 编写日期：2026-08-24  
> 练习主题：生产工单 `SC-20260823-003` 中，将 200 kg 原料 RM-A 替换为 RM-B  
> 重要前提：本文编写时，正式数据库中的平行账套、调整、测算和合并记录全部为 0。需要由测试人员从页面亲手创建第一套平行账套。

---

## 1. 先用一句话理解平行账套

平行账套不是第二套日常 ERP，也不是另一个可以随意改库存的数据库。

它的正确用途是：

```text
从正式账套复制一个确定范围、确定时点的只读快照
→ 在隔离空间提出调整方案
→ 系统重新计算库存、采购、BOM、生产和成本影响
→ 方案可以只保存，不影响正式账
→ 确实需要执行时，把差异转换为正式纠错单据
→ 由有权管理员复核并发布，再通过业务执行回到唯一的正式账套
```

因此，你可以把它理解成“基于正式业务数据的管理决策沙盘”。

## 2. 本次练习要解决什么实际问题

苏州精密传动有限公司下了一张 500 件齿轮箱壳体订单。正式生产工单已经排产，并按当前 BOM 生成了领料需求：

| 正式业务对象 | 编号或内容 |
|---|---|
| 客户 | `SIM-C-001` 苏州精密传动有限公司 |
| 销售订单 | `DD-20260823-005` |
| 客户订单号 | `SIM-PO-PL-001` |
| 生产工单 | `SC-20260823-003` |
| 产品 | `FG-HOUSING` 定制化齿轮箱壳体 |
| 生产数量 | 500 件 |
| 排产日期 | 2026-09-20 |
| 机台 | `CNC-SIM-02` |
| 领料单 | `LL-20260823-002`，待审批、未发料 |

当前正式 BOM 对这张工单的理论需求是：

| 物料 | 正式需求 | 当前正式库存 |
|---|---:|---:|
| `RM-A` 高强度原料A | 1,000 kg | 1,150 kg |
| `AUX-COAT` 防锈涂层液 | 25 L | 120 L |
| `PKG-BOX` 出口周转包装 | 500 套 | 1,080 套 |
| `RM-B` 替代原料B | 当前 BOM 不需要 | 100 kg |

管理层现在提出：

> 不直接改正式 BOM，也不直接让仓库发 RM-B。先测算把工单中的 200 kg RM-A 换成 200 kg RM-B，会不会缺料、成本增加多少、需要补哪些正式手续。

这个问题正适合用平行账套处理。

## 5. 第一阶段：先核对正式业务底稿

### 5.1 核对生产工单

1. 使用 `production` 登录。
2. 进入“生产管理”→“计划与高级操作”。
3. 找到生产工单 `SC-20260823-003`。
4. 核对：
   - 客户订单号为 `SIM-PO-PL-001`；
   - 数量为 500 件；
   - 计划日期为 2026-09-20；
   - 机台为 `CNC-SIM-02`；
   - 状态为已生成领料需求；
   - 尚未正式发料。

为什么必须“尚未发料”：本场景模拟的是执行前的替代料决策。如果 RM-A 已经发出，业务会变成退料、冲销、返工和已发生成本修正，复杂度明显更高。

### 5.2 核对领料需求

找到领料单 `LL-20260823-002`，检查三行需求：

```text
RM-A       1,000 kg
AUX-COAT      25 L
PKG-BOX      500 套
```

不要审批，也不要发料。

### 5.3 核对库存

1. 使用 `warehouse` 登录。
2. 进入“库存仓储”。
3. 检查 RM-A、RM-B、AUX-COAT 和 PKG-BOX。
4. 重点记住 RM-B 只有 100 kg。

后面平行账套提出替换 200 kg 时，系统应识别 RM-B 真实净缺口为 100 kg。

---

## 6. 第二阶段：创建第一套平行账套

### 6.1 进入入口

1. 退出当前账号。
2. 使用 `manager` / `mgr123` 登录。
3. 展开左侧“隔离工作区”。
4. 点击“平行账套”。

此时“我的平行账套”应为空。这不是故障，而是本次特意没有预置任何平行账套数据。

### 6.2 填写创建表单

点击“创建账套”，填写：

| 字段 | 填写内容 |
|---|---|
| 账套名称 | `SC-20260823-003 原料替换测算` |
| 用途说明 | `评估将200kg高强度原料A替换为原料B的库存、采购、领料和成本影响` |
| 基准日期 | `2026-08-23` |
| 测算范围 | `指定生产工单` |
| 具体对象 | `SC-20260823-003` |
| 允许申请合并 | 勾选 |
| 同时注入演示数据 | **不要勾选** |

为什么基准日期填写 2026-08-23：当前这批正式业务事件使用的系统业务日期是 2026-08-23，系统只允许从已有可信业务事件的日期建立快照。

为什么选择“指定生产工单”而不是“全公司”：范围越小，越容易解释影响，也能避免把其他订单、库存和成本无关地带入本次决策。

为什么不能勾选“同时注入演示数据”：那个选项会增加 PAL-A、PAL-B、成品 P 等专用演示资料，与本次真实正式业务底稿无关。

点击“创建账套”。如果这是第一套，系统通常生成类似 `PX-20260823-001` 的账套编码，实际以页面显示为准。

### 6.3 识别当前环境

进入账套后，页面顶部应持续显示：

- “当前为测算环境”；
- 账套名称和编码；
- 基准日期；
- 工作版本，例如 v1；
- 当前状态，例如草稿；
- “允许申请合并”或“仅测算”。

看到这个黄色测算环境标识时，要明确：这里的调整暂时不是真实采购、真实库存或真实成本。

---

## 7. 第三阶段：配置职责分离

进入账套的“成员权限”页签，把 `admin` 配置为本账套的“账套管理员”。财务成员可以按需要选配，但不是合并的必经岗位。

### 7.1 配置账套管理员

1. 用户选择“系统管理员-管理员”。
2. 账套角色选择“账套管理员”。
3. 点击“保存授权”。

预期权限包含“查看、调整、重算、导出、冻结、提交、审批、发布、管理”等账套级能力。

### 7.2 可选配置财务成员

如果希望财务查看或导出测算结果，可以：

1. 用户选择“财务专员-赵会计”。
2. 只需查看时选择“观察员”；需要参与测算时选择“测算员”。
3. 点击“保存授权”。

不配置 `finance` 也不影响管理员审批和发布合并。

### 7.3 为什么仍要分开申请人与管理员

```text
manager 提出方案并提交
→ admin 作为账套管理员独立复核
→ admin 直接发布正式纠错包
```

这里保留“申请人不能审批自己的申请”的控制，但不再强制财务二次发布。也就是说，`manager` 提交后，`admin` 可以在同一账号中连续完成“同意合并”和“发布到正式账套”。即使系统角色很高，也必须先成为当前账套的明确成员，才能看到并操作该账套的敏感内容。

### 7.4 验证普通员工隔离

1. 退出 `manager`。
2. 使用 `sales` 登录。
3. 检查左侧导航、全局搜索和导出入口。
4. 销售账号不应看到刚创建的账套，也不应看到其名称、成员、调整和测算结果。
5. 重新使用 `manager` 登录继续。

仅仅隐藏菜单不算完全隔离；直接地址、接口和导出也必须拒绝未授权用户。

---

## 8. 第四阶段：录入“RM-A 替换 RM-B”调整

### 8.1 新增调整

1. 打开刚创建的账套。
2. 进入“调整项”。
3. 点击“新增调整”。
4. 填写：

| 字段 | 填写内容 |
|---|---|
| 调整类型 | `物料替换` |
| 生效日期 | `2026-09-20` |
| 生产工单 | `SC-20260823-003` |
| 原物料 | `高强度原料A`，编码 RM-A |
| 替代物料 | `替代原料B`，编码 RM-B |
| 替换数量 | `200` |
| 调整原因 | `SC-20260823-003 中将200kg RM-A替换为RM-B，用于验证替代料可行性` |

5. 点击“保存调整”。

保存后工作版本一般从 v1 增加到 v2，因为你已经在原始快照上增加了一项差异。

### 8.2 这一步没有做什么

保存调整时，系统不应：

- 修改正式 BOM；
- 把 RM-A 正式库存减少 200 kg；
- 把 RM-B 正式库存增加或减少；
- 修改正式领料单；
- 自动创建正式采购订单；
- 改变正式工单成本。

它只记录“如果这样替换，结果会怎样”的测算输入。

## 9. 第五阶段：重新测算并读懂结果

点击页面顶部“重新测算”。测算完成后，账套状态应变为“测算完成”。

### 9.1 先看总体结论

按当前正式数据，预期接近：

| 指标 | 预期结果 |
|---|---:|
| 纳入测算的生产工单 | 1 |
| 调整项 | 1 |
| 真实物料净缺口种类 | 1 |
| 基准工单总成本 | 约 37,114.50 元 |
| 替换后工单总成本 | 约 37,485.50 元 |
| 成本增加 | 约 371.00 元 |
| 替换后单位成本 | 约 74.97 元/件 |
| RM-B 采购缺口 | 100 kg |
| RM-B 预计采购金额 | 1,200 元 |

为什么不是增加 400 元：历史采购完成后，RM-A 使用移动平均成本，不再刚好是 10 元/kg；RM-B 当前平均成本为 12 元/kg。系统按现有移动均价计算，所以实际差异约为 371 元。

报价金额 46,250 元与这里的 37,485.50 元不能直接比较：前者是含利润的销售报价，后者是工单测算成本。

### 9.2 看“影响分析”

应该能看到以下业务含义：

1. BOM 域：RM-A → RM-B 的替换缺少正式配方/变更依据。
2. 生产域：工单需要补领 RM-B 200 kg。
3. 库存域：RM-B 正式库存 100 kg，替换需求 200 kg，净缺口 100 kg。
4. 采购域：建议采购 RM-B 100 kg，预计单价 12 元，金额 1,200 元。
5. 成本域：工单总成本约增加 371 元。

### 9.3 看“物料缺口与建议”

系统应产生 4 类建议：

| 建议 | 为什么需要 |
|---|---|
| 采购申请 | RM-B 还缺 100 kg |
| BOM/配方变更依据 | 不能无依据地把 RM-A 改为 RM-B |
| 补料单 | 工单需要补领 RM-B 200 kg |
| 工单成本调整 | 替代料价格不同，工单成本发生变化 |

本场景不会产生正式退料单，因为领料单仍处于待审批，RM-A 尚未正式出库。如果先把 RM-A 发料，再做替换，系统才应进一步处理退料或冲销。

页面可能同时展示几条与 RM-B 相关的逻辑缺口：配方依据、补料依据、成本差异和物理库存缺口。判断“实际要买多少”时，以采购建议中的净缺口 100 kg 为准，不要把这些逻辑行简单相加。

### 9.4 建议不是正式单据

此时打开正式采购管理、正式 BOM、仓库和成本模块，不应看到这 4 条建议已经被执行。它们仍然只属于当前平行账套。

## 10. 第六阶段：只做测算、不合并

如果你的目标只是比较方案，到这里就可以停止。

建议执行以下检查：

1. 打开“导出”，下载“调整前后差异表”“物料缺口与建议”“工单成本测算”和“调整明细”。
2. 导出文件应包含“平行账套/测算数据”、账套编码、版本、基准日期和导出时间。
3. 刷新页面或重新登录，账套、调整和测算结果仍然存在。
4. 再次检查正式库存：RM-A、RM-B 数量不应因测算而改变。
5. 不再使用时，可以点击“归档”。

这就是“平行账套独立保存”的完整用法：可以长期留作经营测算和历史复盘，但不会进入正式经营数据。

如果只是学习界面，建议第一次操作先停在这里。熟悉后再继续下面的合并闭环。

---

## 11. 第七阶段：把方案提交为正式纠错申请

### 11.1 接受建议

在“物料缺口与建议”中，逐项检查并点击“接受”：

- RM-B 100 kg 采购申请；
- BOM/配方变更；
- RM-B 200 kg 补料；
- 工单成本调整。

接受的含义是“同意把这项建议纳入未来正式纠错包”，仍然不等于正式执行。

### 11.2 冻结版本

1. 点击“冻结版本”。
2. 账套状态应变为“已冻结”。
3. 冻结后不能继续新增或删除调整。

如果发现参数写错，点击“解冻修改”，改完后必须重新测算、重新检查建议，再次冻结。

### 11.3 合并预览

点击“合并预览”，重点检查预览中不是“覆盖数据库”，而是包含以下差异单据：

```text
采购申请
BOM/配方变更纠错
生产补料纠错
工单成本调整纠错
```

如果正式工单在创建平行账套后又被其他人修改，预览可能显示冲突。此时不要强行发布，应点击“吸收正式变更并重新基线”，然后重新测算和确认。

### 11.4 提交合并

1. 确认所有建议已处理、版本已冻结。
2. 点击“提交合并”。
3. 系统应生成类似 `PHB-20260823-001` 的合并申请号。
4. 状态变为“合并审批中”。

提交人不能审批自己的申请；但已被授权为“账套管理员”的 `admin` 可以审批后直接发布，不需要再切换到 `finance`。

---

## 12. 第八阶段：审批和发布

### 12.1 管理员独立审批

1. 退出 `manager`。
2. 使用 `admin` / `admin123` 登录。
3. 进入“隔离工作区”→“平行账套”。
4. 打开这套账，找到合并申请。
5. 点击“同意合并”。
6. 审批意见可填写：`同意按建议单据包执行，替代料到货后继续正式纠错。`

### 12.2 管理员直接发布正式纠错包

1. 审批通过后继续使用当前 `admin` 账号，不需要退出。
2. 打开同一账套，确认合并申请状态为“已批准”。
3. 点击“发布到正式账套”。

`finance` 不是这一流程的必经岗位。只有企业内部另有“财务必须复核后发布”的制度时，才需要把财务配置为“发布人”。

按当前库存，发布后预期不是立即全部完成，而是：

- 合并申请状态：`execution_pending`，页面中文含义为等待外部业务条件；
- 账套状态：正式纠错执行中；
- 已生成正式采购申请：RM-B 100 kg，金额约 1,200 元；
- 已生成 BOM 变更、补料和成本调整纠错记录；
- 提示：`替代原料B 尚缺 100，需采购到货并完成入库后继续执行。`

这是正确行为。系统没有为了“合并成功”而虚增库存，也没有在缺料时强行执行补料。

重复点击发布不应生成第二套采购申请或第二套纠错单，这就是幂等保护。

---

## 13. 第九阶段：完成 RM-B 采购并继续执行

### 13.1 采购申请转采购订单

1. 使用 `purchasing` / `pur123` 登录。
2. 进入“采购管理”→“采购全流程”。
3. 找到来源类型为“平行账套合并”的 RM-B 采购申请。

## 15. 常见疑问和处理方法

### 15.1 为什么平行账套列表一开始是空的

因为本次按要求没有预置任何平行账套数据。正式订单、工单、库存和采购数据已经准备好，但第一套平行账套需要你自己创建。

### 15.2 为什么普通员工看不到入口

这是权限隔离的预期结果。普通员工继续在唯一正式账套办理采购、生产、仓储和销售，不应知道未授权平行账套的名称或内容。

### 15.3 为什么替换 200 kg，只建议采购 100 kg

因为正式库存已有 RM-B 100 kg：

```text
替换需求 200 kg - 可用库存 100 kg = 净缺口 100 kg
```

### 15.4 为什么有成本增加，却没有立即修改正式成本

测算结果只是决策依据。只有差异被接受、冻结、审批、发布，且采购和库存条件满足后，正式成本调整单才会执行。

### 15.5 为什么发布后停在“等待执行”

因为 RM-B 还没完成真实采购和入库。平行账套不能虚构到货，也不能绕过采购、仓库和 IQC。完成外部业务后再点击“复检并继续正式执行”。

### 15.6 为什么本场景没有退料单

因为 `LL-20260823-002` 尚未发料。RM-A 只存在理论需求，没有形成已出库数量，因此不需要退回已发物料。

### 15.7 如果正式工单在测算期间被修改怎么办

执行合并预览时会出现冲突。使用“吸收正式变更并重新基线”，重新测算、确认建议和冻结，不能拿旧快照直接覆盖新业务。

### 15.8 如果不想合并怎么办

保持“测算完成”状态、导出结果后归档即可。独立保存是平行账套的正常终点之一，不是未完成。
