# ERP 平行账套新版功能操作手册

> 适用版本：2026-08-25 平行账套原生业务单据链版本  
> 适用角色：系统管理员、管理层、财务及获授权的平行账套成员  
> 当前环境：原平行账套测试数据已清空，可以从零开始操作

## 1. 先用一句话理解平行账套

平行账套是从正式 ERP 某个时间点复制出来的一套独立测算环境。

你可以在里面假设“原料 A 改成 B”“采购价上涨”“产量变化”等情况，系统会重新计算库存、采购、生产和成本，并在平行账套内生成看起来与正常 ERP 一样的业务单据。

平行账套中的操作不会直接改变正式账套。只有经过冻结、预览、提交、审批和发布后，系统才会把差异转换成正式业务动作。

## 2. 它不是什么

平行账套不是第二套正式 ERP，也不是用一套数据库直接覆盖另一套数据库。

需要特别区分：

- 在平行账套点击“完成采购入库”，增加的是模拟库存，正式库存不会增加。
- 在平行账套完成全部业务单据，表示这个方案在模拟环境中可以跑通，不表示正式业务已经发生。
- “发布到正式账套”发布的是差异和正式执行动作，不是把平行账套整库替换到正式账套。
- 如果正式账套仍然缺少真实库存、采购到货或其他业务条件，正式执行仍会等待，不会强行完成。

## 3. 新版完整操作流程

```text
创建平行账套
  → 新增假设调整
  → 重新测算
  → 查看影响和缺口
  → 按顺序完成模拟业务单据
  → 再次重新测算
  → 核对成本与库存结果
  → 选择仅保留、放弃，或提交合并
```

如果只是向领导展示一个方案，做到“核对成本与库存结果”即可，不需要提交合并。

## 4. 推荐验收场景：生产工单中将 200 kg 原料 A 替换为 B

当前正式账套已有以下可用数据：

| 业务对象 | 当前数据 |
|---|---|
| 生产工单 | `SC-20260823-003` |
| 产品 | `FG-HOUSING`，定制化齿轮箱壳体，500 件 |
| 原物料 | `RM-A`，高强度原料 A，正式库存 1,150 kg |
| 替代物料 | `RM-B`，替代原料 B，正式库存 100 kg |
| 工单原始需求 | RM-A 1,000 kg、AUX-COAT 25 L、PKG-BOX 500 套 |
| 本次模拟 | 将其中 200 kg RM-A 替换为 RM-B |

替换后 RM-B 理论需求为 200 kg，但基准正式库存只有 100 kg，因此第一次测算预计出现约 100 kg 的 RM-B 缺口。

### 4.1 登录并进入平行账套

1. 打开系统：`http://localhost:3001`。
2. 使用 `admin / admin123` 登录。
3. 在左侧打开“基础与协作”或“隔离工作区”。
4. 点击“平行账套”。
5. 当前列表应为空，点击右上角“创建账套”。

### 4.2 创建账套

按下面填写：

| 字段 | 建议内容 |
|---|---|
| 账套名称 | `SC-20260823-003 原料A替换B模拟` |
| 用途说明 | `验证200kg原料A替换为B后的采购、库存、补料和成本变化` |
| 基准日期 | `2026-08-23` |
| 测算范围 | `指定生产工单` |
| 具体对象 | `SC-20260823-003` |
| 允许申请合并 | 测试完整合并流程时勾选；只做方案测算时可以取消 |
| 同时注入演示数据 | **不要勾选**，本次直接使用正式账套现有业务快照 |

点击“创建账套”，然后在列表中点击“进入”。

页面顶部出现“当前为测算环境”表示已经进入隔离环境。

### 4.3 新增原料替换调整

1. 打开“调整工作区”。
2. 点击“新增调整”。
3. 填写：

| 字段 | 内容 |
|---|---|
| 调整类型 | `工单原料替换` |
| 生效日期 | `2026-08-23` |
| 原因 | `客户方案验证：SC-20260823-003 中200kg RM-A替换为RM-B` |
| 生产工单 | `SC-20260823-003` |
| 原物料 | `高强度原料A（RM-A）` |
| 替代物料 | `替代原料B（RM-B）` |
| 替换数量 | `200` |

4. 点击“保存调整”。
5. 检查调整项列表中出现一条原料替换记录。

此时只是登记了一个模拟假设，还没有重新计算。

### 4.4 第一次重新测算

1. 点击页面上方“重新测算”。
2. 打开“总览”，查看工单数、调整项数、缺口数和成本变化。
3. 打开“影响分析”，查看 BOM、库存、生产领料和成本受到哪些影响。
4. 打开“缺口与建议”，预计看到 RM-B 缺少约 100 kg。
5. 对准备纳入后续方案的建议点击“接受”。

“缺口与建议”负责解释系统为什么需要做这些业务；真正推进模拟过程，请进入“业务单据”。

### 4.5 查看系统生成的正常业务单据

进入“业务单据”，系统预计自动生成：

1. BOM 变更单；
2. RM-B 采购申请；
3. RM-B 采购订单；
4. RM-B 采购到货单；
5. RM-B 采购入库单；
6. RM-B 生产补料单；
7. 工单成本调整单。

本场景的正式领料单尚未实际发料，所以通常不会生成 RM-A 退料单。如果正式历史中已经发出 RM-A，系统才会根据已发数量自动增加生产退料单。

单据编号会使用模拟业务日期，例如：

```text
BG-20260823-001  BOM变更单
QS-20260823-001  采购申请
CG-20260823-001  采购订单
DH-20260823-001  采购到货单
RK-20260823-001  采购入库单
BL-20260823-001  生产补料单
CB-20260823-001  工单成本调整单
```

具体流水号以页面实际结果为准。

## 5. 怎么完成自动生成的单据链

必须从上到下操作。系统会阻止跳过上游单据。

### 5.1 完成 BOM 变更单

1. 找到状态为“可以完成”的 BOM 变更单。
2. 点击“完成”。
3. 完成后，采购申请才会进入可完成状态。

### 5.2 完成采购申请

1. 找到采购申请。
2. 确认数量约为 100 kg。
3. 点击“完成”。

采购申请完成后，采购订单仍会显示“等待补充信息”，因为供应商、价格和交期属于系统不能凭空推断的外部事实。

### 5.3 完善并完成采购订单

1. 在采购订单行点击“补充信息”。
2. 填写：

| 字段 | 测试值 |
|---|---|
| 供应商 | `SUP-MT61ZR9G-75HVS`（常州合金材料有限公司） |
| 采购单价 | `12` |
| 预计到货日期 | `2026-08-25` |

3. 点击“保存信息”。
4. 状态变成“可以完成”后，点击“完成”。

### 5.4 完善并完成采购到货单

1. 在采购到货单点击“补充信息”。
2. 填写：

| 字段 | 测试值 |
|---|---|
| 实际到货日期 | `2026-08-25` |
| 实际数量 | `100` |

3. 保存后点击“完成”。

### 5.5 完善并完成采购入库单

1. 在采购入库单点击“补充信息”。
2. 填写：

| 字段 | 测试值 |
|---|---|
| 入库日期 | `2026-08-25` |
| 实际数量 | `100` |
| 批次号 | `RMB-SIM-20260825-001` |
| 仓库 | `WH-RM-01` |
| 入库单价 | `12` |

3. 保存后点击“完成”。

完成这一步后，100 kg 只进入平行账套的模拟采购数量，正式账套的 RM-B 库存仍然是 100 kg。

### 5.6 入库后必须再次重新测算

1. 点击页面上方“重新测算”。
2. 系统将原有 100 kg RM-B 与模拟入库 100 kg 合并计算。
3. RM-B 的 200 kg 模拟需求得到满足。
4. 生产补料单应从“等待模拟库存”变成“可以完成”。

重新测算不会重复生成第二套采购申请、采购订单或入库单，已经完成的单据仍会保留。

### 5.7 完成补料和成本单据

1. 完成 RM-B 生产补料单。
2. 完成工单成本调整单。
3. 检查页面完成进度，预计为 `7 / 7`。

如果系统生成了 RM-A 生产退料单，应先完成退料单，再完成成本调整单。

## 6. 怎么判断模拟结果是否合理

完成业务单据链后检查四个地方：

### 6.1 总览

确认：

- 调整项数量正确；
- 生产工单范围正确；
- 测算成本与基准成本差额可以解释；
- 缺口数在模拟入库后下降。

### 6.2 影响分析

确认系统已经识别：

- 原料替换对 BOM 的影响；
- RM-B 的采购和库存影响；
- 工单补料影响；
- 生产成本变化。

### 6.3 差异对比

检查：

- 原料成本是否由 RM-A 单价切换到 RM-B 单价；
- 库存投影是否包含模拟入库；
- 单位成本和总成本变化是否合理。

### 6.4 报表导出

可以导出差异表、缺口建议、工单成本、库存汇总和收发存测算。

导出的文件属于平行账套测算报表，不代表正式账套已经过账。

## 7. 测算完成以后有三种选择

### 7.1 仅保留方案

适合领导查看、内部讨论或以后复盘。

不需要冻结或提交合并，直接保留账套即可。

### 7.2 放弃方案

点击“放弃方案”。平行账套停止继续使用，正式账套不受影响。

### 7.3 准备合并到正式账套

只有确定方案需要进入正式业务时才执行：

1. 确认业务单据链已经完整；
2. 确认“缺口与建议”中的必要建议已经接受；
3. 点击“冻结版本”；
4. 点击“合并预览”；
5. 检查是否存在正式数据变化冲突；
6. 点击“提交合并”；
7. 管理员可以直接审批自己提交的申请；
8. 审批后点击“发布到正式账套”。

## 8. 为什么模拟已经入库，正式发布仍可能等待

这是最容易误解的地方。

平行账套中的采购入库只是为了证明方案在假设条件下可以闭环。它不能证明现实中的供应商已经发货，也不能给正式仓库虚增库存。

因此本场景发布后，如果正式 RM-B 仍只有 100 kg，系统可能：

- 在正式账套生成 RM-B 100 kg 的采购申请；
- 将合并申请置为 `execution_pending`；
- 提示先完成正式采购、到货和入库；
- 等正式库存满足后，再点击“复检并继续正式执行”。

这不是合并失败，而是正式执行正在等待真实业务条件。

## 9. 页面状态是什么意思

| 页面状态 | 含义 | 你应该怎么做 |
|---|---|---|
| 可以完成 | 信息和上游条件都满足 | 点击“完成” |
| 等待补充信息 | 缺少供应商、价格、日期、数量或批次 | 点击“补充信息” |
| 等待上游单据 | 前面的单据还没完成 | 先完成上游单据 |
| 等待模拟库存 | 平行账套中的可用库存不足 | 完成模拟采购入库，再重新测算 |
| 已完成 | 该模拟业务已经确认 | 继续处理下一张单据 |
| 需要复核 | 新测算条件与已经完成的单据不一致 | 检查调整项和最新影响 |

## 10. 常见错误

### 10.1 创建账套后什么都没有

原因：还没有新增调整，或者新增调整后没有点击“重新测算”。

### 10.2 业务单据为空

原因：当前调整没有形成需要复盘的原料替换业务，或者测算尚未成功。

### 10.3 采购订单不能完成

原因：供应商、采购单价或预计到货日期没有填写完整，或者采购申请尚未完成。

### 10.4 补料单一直等待库存

依次检查：

1. 采购订单是否完成；
2. 到货单是否完成；
3. 入库单是否完成；
4. 入库数量是否足够；
5. 入库完成后是否再次点击“重新测算”。

### 10.5 点击重新测算会不会重复生成单据

不会。同一个调整、工单、物料和单据类型使用固定生成键，重新测算只刷新原单据和状态。

### 10.6 可以直接把平行账套覆盖到正式账套吗

不可以。系统只会计算差异，通过审批和正式执行动作发布，防止覆盖正式库存、生产和财务记录。

## 11. 本次从零测试的完成标准

- 平行账套从空列表开始创建；
- RM-A 替换 RM-B 的调整保存成功；
- 系统识别约 100 kg RM-B 缺口；
- 自动生成 BOM、采购、到货、入库、补料和成本单据链；
- 缺少字段时不能强行完成；
- 上游未完成时下游不能完成；
- 模拟入库后重新测算，补料单可以继续；
- 正式 RM-B 库存始终没有因为模拟入库而变化；
- 重复重新测算不产生重复单据；
- 未授权普通账号看不到平行账套。
