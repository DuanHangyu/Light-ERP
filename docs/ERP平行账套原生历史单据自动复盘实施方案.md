# ERP 平行账套原生历史单据自动复盘实施方案

> 版本：V1.0  
> 日期：2026-08-24  
> 状态：进入开发

## 1. 能力定义

少数获授权的管理人员在平行账套中修改历史业务条件后，系统自动复盘受影响的 BOM、采购、库存、领退料和成本链路，并在平行账套内生成与正式 ERP 形态一致的模拟业务单据。用户补齐系统无法推断的外部事实后，可以按依赖顺序推进整条模拟业务链；所有操作只改变平行账套，不直接改变正式账套。

平行账套内的单据使用正常业务名称、编号、业务日期和状态，不在单据名称或内容中显示“追溯补录”“纠错”字样。页面顶部的账套环境提示承担环境识别职责。

## 2. 固定规则

1. **正式账隔离**：平行单据不得写入正式采购、库存、BOM、生产或成本表。
2. **原生单据形态**：平行账内展示 BOM 变更、采购申请、采购订单、到货、入库、退料、补料和成本调整等正常业务单据。
3. **自动生成**：重算成功后按影响和缺口自动生成单据链，不要求用户逐张手工新建。
4. **缺失信息待补**：供应商、实际价格、到货日期、批次和仓库等无法推断的信息进入待补字段，不伪造默认事实。
5. **不强行过账**：前置单据未完成、库存不足或必要字段缺失时，后续单据保持等待状态。
6. **幂等**：同一账套版本、来源调整、业务对象和单据类型只能存在一张有效模拟单据；重新计算不得重复生成。
7. **可重算**：调整变化后，系统更新尚未完成的模拟单据；已完成单据保留并标记需要复核，不静默覆盖用户已确认的业务事实。
8. **后台追溯**：后台保留账套、版本、来源调整、来源建议、生成键和依赖关系，前台不展示“补录/纠错”标签。
9. **受控合并**：平行单据不能整库覆盖正式账；合并仍按差异形成正式执行动作。

## 3. 用户场景：原料 A 替换为 B

用户在某张生产工单中把原料 A 替换为原料 B 2 吨，系统重新计算后生成：

```text
BOM 版本变更
  → B 采购申请
  → B 采购订单（等待供应商、单价和日期）
  → B 到货单（等待采购订单完成）
  → B 入库单（等待到货数量、批次和仓库）
  → A 退料单（仅在 A 已领且理论用量下降时生成）
  → B 补料单（B 可用库存不足时等待入库）
  → 工单成本调整（等待领退料完成）
```

用户补齐采购订单与到货信息后，系统可以继续推进模拟采购和入库；平行库存满足后，补料和成本单据才可完成。

## 4. 单据状态

| 状态 | 中文含义 | 是否允许完成 |
|---|---|---|
| `ready` | 信息完整且前置条件满足 | 是 |
| `waiting_input` | 等待用户补充必要字段 | 否 |
| `waiting_dependency` | 等待上游单据完成 | 否 |
| `waiting_inventory` | 等待模拟库存满足 | 否 |
| `completed` | 已在平行账套内完成 | 否，保持只读 |
| `needs_review` | 重新计算后已完成单据与新结果不一致 | 否，需复核 |

单据依赖顺序固定为：

```text
BOM依据 → 采购申请 → 采购订单 → 到货 → 入库 → 退/补料 → 成本
```

## 5. 数据模型

新增 `parallel_simulation_documents`：

| 字段 | 说明 |
|---|---|
| `id` | 内部主键 |
| `ledger_id` | 所属平行账套 |
| `run_id` | 最近一次计算批次 |
| `generation_key` | 幂等生成键 |
| `document_type` | 原生业务单据类型 |
| `document_no` | 平行账内正常业务编号 |
| `business_date` | 模拟业务发生日期 |
| `sequence_no` | 执行顺序 |
| `dependency_key` | 上游单据生成键 |
| `status` | 单据状态 |
| `title` | 正常业务标题 |
| `payload_json` | 已知及用户补充字段 |
| `required_fields_json` | 必填字段定义 |
| `missing_fields_json` | 当前缺失字段 |
| `blocking_reason` | 当前不能推进的原因 |
| `source_adjustment_id` | 来源调整 |
| `source_suggestion_id` | 来源建议 |
| `completed_by/at` | 模拟完成信息 |
| `created_at/updated_at` | 系统时间 |

`generation_key` 在同一账套内唯一，格式由“来源调整 + 工单/物料 + 单据类型”稳定生成。

## 6. 服务接口

### 6.1 自动生成

平行账重算成功后调用单据链生成器：

- 将物料替换影响转换为 BOM、补料、退料和成本单据；
- 将实际物料缺口展开为采购申请、采购订单、到货和入库单据；
- 根据已有领料与库存决定是否阻断；
- 对未完成单据执行幂等更新。

### 6.2 补充信息

动作：`parallelLedgerUpdateSimulationDocument`

输入：单据 ID 与业务字段。服务端只允许更新白名单字段，重新计算缺失字段和状态，并写审计日志。

### 6.3 推进单据

动作：`parallelLedgerCompleteSimulationDocument`

完成前校验：

- 必填字段全部填写；
- 依赖单据已完成；
- 补料单的模拟库存足够；
- 单据所属账套仍可调整。

完成入库单时，系统在平行账中增加对应的计划采购数量，再重新计算库存和后续状态，不写正式库存。

## 7. 页面方案

平行账详情增加“业务单据”页签，包含：

1. 单据链完成进度；
2. 按执行顺序排列的原生单据表；
3. 正常单据编号、日期、对象、金额/数量和状态；
4. 缺失字段及阻断原因；
5. “补充信息”和“完成”操作；
6. 单据详情中展示正常业务字段，不显示补录或纠错标签。

原“建议单据”继续作为计算解释层，业务人员实际操作以“业务单据”页签为主。

## 8. 验收标准

1. A 换 B 且 B 缺料时，自动生成完整采购至入库链和 BOM、补退料、成本链。
2. 所有平行单据使用正常业务名称，不显示“补录/纠错”。
3. 采购订单缺少供应商、价格或日期时不能完成，并明确列出缺失字段。
4. 入库单未完成前，B 补料单不能完成。
5. 完成模拟入库后重新计算，平行库存增加，正式库存不变。
6. 重复重算不产生重复单据。
7. 无查看或调整权限的账号无法读取或推进单据。
8. 每次补充字段和完成动作写入审计日志。
9. 原有建议确认、冻结、合并、正式执行与对账流程保持兼容。
