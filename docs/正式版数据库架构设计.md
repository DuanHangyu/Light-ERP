# 轻量级定制生产流转 ERP 正式版数据库架构设计

## 1. 当前结论

当前系统已经不是前端假数据，所有业务动作都会写入本地 SQLite 数据库文件，库存、成本、应收应付、审批、配方试算和审计日志都会持久化保存。

但当前库中的业务内容属于演示种子数据。正式部署时应使用生产初始化模式，只创建基础角色账号和数据库结构，不写入演示客户、订单、库存、报价、采购单等业务数据。

## 2. 正式版数据库定位

第一期功能确认版采用 SQLite 作为本地单机数据库，数据库文件与附件统一放在 `ERP_DATA_DIR` 指向的数据盘目录下。该方案适合客户当前小团队、低并发、纯局域网私有化部署要求。

后续如果客户多工厂、多部门并发明显增加，可平滑升级到 PostgreSQL。业务表设计保持标准关系型结构，避免把核心业务长期锁死在临时 JSON 或前端状态中。

## 3. 数据目录与启动模式

正式部署建议使用独立物理数据盘：

```bash
ERP_DATA_DIR=/Volumes/ERP_DATA
ERP_SEED_MODE=production
npm run start
```

模式说明：

- `ERP_SEED_MODE=demo`：用于演示环境，自动写入客户、物料、库存、订单、采购、审批、配方试算等演示数据。
- `ERP_SEED_MODE=production`：用于正式环境，只创建基础角色账号和空业务库，不混入任何演示业务数据。

## 4. 核心数据域

### 4.1 基础主数据

- `users`：用户、角色、岗位标签。
- `customers`：客户资料，包含客户编码、联系人、电话、状态、地址、税号、备注、创建/更新时间。
- `suppliers`：供应商资料与账期，包含供应商编码、联系人、电话、状态、地址、税号、付款条件、备注、创建/更新时间。
- `materials`：物料主档，包含物料编码、名称、规格、单位、库存数量、移动均价、安全库存、最近变动时间、状态、备注、创建/更新时间。
- `products`：产品主档，包含产品编码、名称、规格、单位、加工费、默认利润率、状态、备注、创建/更新时间。
- `boms` / `bom_lines`：多级 BOM 与主材标记，BOM 主表记录版本、状态、备注、创建/更新时间。
- `material_substitutes`：替代料关系。

主数据设计按正式产品要求保留独立业务编码字段，不直接把数据库主键当作客户可见编号。当前第一期可默认使用同值初始化，后续上线时可按客户编码规则调整为 `KH-年月-序号`、`WL-分类-序号` 等格式。

### 4.2 销售与订单

- `quotes`：报价单、版本、材料成本、加工费、利润率、报价总额。
- `orders`：客户订单、交期、特殊要求、订单状态。
- `shipments`：发货单、发货数量、发货时间、发货状态。
- `receivables` / `receivable_receipts`：应收账款与回款记录。

### 4.3 生产执行

- `production_orders`：生产指令单。
- `schedules`：人工排产记录，包括计划日期、机台、负责人。
- `requisitions` / `requisition_lines` / `requisition_allocations`：领料单、领料明细、批次分配与替代料发料记录。

### 4.4 仓储与成本

- `material_batches`：原材料批次库存、批次成本、入库时间、最近变动时间。
- `finished_batches`：成品/过渡料批次、入库数量、单位成本、收率。
- `inventory_movements`：库存流水，记录采购入库、领料出库、成品入库、发货等所有库存变动。

成本规则：

- 采购入库按移动加权平均法更新物料均价。
- 出库后按剩余批次库存重新计算物料均价。
- 所有库存变动写入 `inventory_movements`，用于追溯和报表。

### 4.5 采购与应付

- `purchase_orders` / `purchase_order_lines`：采购订单与采购明细。
- `payables` / `payable_payments`：应付账款与付款记录。

### 4.6 品控与收率

- `inspections`：请验单、检验结果、实际入库量、主材领用量、收率。

品控闸门：

- 只有合格或让步接收批次允许进入成品入库。
- 不合格批次保留检验记录，不推送入库。

### 4.7 OA 审批与配方算价

- `approval_requests`：OA 审批单、申请人、金额、原因、审批人、审批意见。
- `formula_price_calculations`：配方试算主表，记录材料成本、加工费、损耗率、利润率、建议单价。
- `formula_price_lines`：配方材料组成明细，记录每种原材料当前均价、用量、成本贡献和占比。

### 4.8 报表、审计与归档

- `document_exports`：所有导出记录，包括报价单、送货单、对账单、日报、月报、积压库存报表。
- `report_snapshots`：日报/周报/月报生成快照。
- `audit_logs`：所有关键操作留痕。
- `schema_migrations`：数据库迁移记录。
- `database_meta`：数据库环境元信息，例如当前初始化模式。

## 5. 迁移策略

正式版采用迁移登记机制：

- 每次结构调整都进入 `schema_migrations`。
- 已执行迁移不得修改，只能新增迁移。
- 结构迁移和数据修复分开执行。
- 生产库不手工改表。

当前正式迁移：

- `001_core_indexes`：为订单、生产、库存、采购、应收应付、审计、导出记录建立核心查询索引。
- `002_master_data_governance_schema`：为客户、供应商、物料、产品、BOM 增加正式主数据治理字段，包括业务编码、状态、规格、地址、税号、备注、创建时间、更新时间。
- `003_master_data_governance_backfill`：为历史演示数据和既有数据回填业务编码、状态、创建时间、更新时间，并为主数据业务编码建立唯一索引。

## 6. 索引设计原则

第一期索引重点服务真实使用中的高频查询：

- 按状态查看待办：订单状态、采购状态、领料状态、请验状态。
- 按日期查看交期、账龄、到期付款。
- 按实体追溯流水：库存流水、审计日志。
- 按客户/供应商查看应收应付。
- 按导出类型查看历史单据。
- 按客户编码、供应商编码、物料编码、产品编码保证主数据唯一性。

## 7. 正式数据初始化流程

正式客户环境建议流程：

1. 配置 `ERP_DATA_DIR` 指向独立数据盘。
2. 配置 `ERP_SEED_MODE=production`。
3. 启动系统，自动创建数据库结构、迁移记录、基础角色账号。
4. 系统管理员登录后导入或录入客户、供应商、物料、产品、BOM。
5. 业务从真实报价单开始流转。

## 8. 第一阶段主数据管理能力

第一阶段功能确认版已经将主数据从“只读演示数据”升级为可维护的正式业务资料：

- 客户主档：支持新增、编辑、停用，维护客户编码、联系人、电话、地址、税号、备注，并关联订单数与应收余额。
- 供应商主档：支持新增、编辑、停用，维护供应商编码、联系人、电话、账期、地址、税号、备注，并关联应付余额。
- 物料主档：支持新增、编辑、停用，维护物料编码、规格、单位、分类、安全库存、状态、备注；库存数量和移动均价仍通过采购入库、领料出库等业务流水生成，不建议人工直接改库存。
- 产品主档：支持新增、编辑、停用，维护产品编码、规格、单位、加工费、默认利润率、状态、备注，并关联订单与 BOM 版本。
- BOM 主档：支持新增正式版本、停用旧版本。新增版本时系统会保留版本、产品、首行物料、单位用量、主材标记和备注，为后续多行 BOM 编辑和 Excel 导入扩展保留结构。

所有主数据写操作均走服务端接口，执行角色权限校验、编码唯一校验、数据库事务和审计日志记录。停用采用状态变更，不物理删除历史资料，避免影响已发生订单、采购、库存和财务台账的追溯。

主数据导入/导出能力：

- 客户、供应商、物料、产品、BOM 均支持 XLSX / CSV 导出。
- 每类主数据均支持下载标准导入模板，模板字段与正式数据库字段一致。
- 导入时按业务编码自动识别新增或更新，避免重复建档。
- BOM 导入支持同一产品、同一版本多行组件，并自动停用旧启用版本，保留历史版本追溯。
- 物料库存数量、移动均价、批次数量不通过主数据导入直接修改，仍由采购入库、领料出库、成品入库等库存流水产生。
- 每次导出会写入 `document_exports`，每次导入/更新会写入 `audit_logs`，满足后续审计和备份归档要求。

## 9. 销售报价与订单录入能力

销售模块已经从演示流转升级为正式业务录入入口：

- 销售员或系统管理员可在销售订单模块选择客户、产品、报价数量和利润率创建报价单。
- 系统按产品启用 BOM 递归展开物料需求，读取物料当前移动均价，自动计算材料成本。
- 系统叠加产品主档中的加工费，并按录入利润率生成报价总额。
- 报价单先进入草稿状态，确认后可按录入交付日期和特殊要求转为正式客户订单。
- 报价创建、报价确认、订单生成全部写入审计日志。
- 服务层已经加入集成测试，覆盖“正式报价录入 -> 确认报价 -> 转正式订单”主线。

该能力是第一期正式版的关键入口，后续生产指令、排产、领料、请验、入库、发货和应收都围绕正式订单继续流转。

## 10. 从 SQLite 升级 PostgreSQL 的路径

SQLite 适合第一期本地确认版和小团队正式使用。若后续需要更强并发和运维能力，可升级 PostgreSQL：

- 表结构保持同名同字段。
- 将 `better-sqlite3` 数据访问层替换为 PostgreSQL 驱动或查询构建器。
- 迁移记录保留 `schema_migrations` 思路。
- 附件与导出文件仍保留在本地数据盘。
- 备份从 SQLite 文件备份升级为 `pg_dump` + 附件目录备份。

## 11. 设计边界

第一期不做复杂多租户、不做分库分表、不接银行流水、不直接对接用友/金蝶。财务仍通过导出标准台账方式协同。

第一期重点是把订单主线、采购仓储、移动均价、FIFO、品控入库、应收应付、审批算价、报表导出、本地归档做成可信、可追溯、可上线的数据闭环。
