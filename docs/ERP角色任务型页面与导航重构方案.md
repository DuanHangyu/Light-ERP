# ERP 角色任务型页面与导航重构方案

> 版本：v2.0  
> 编制日期：2026-08-21  
> 状态：产品与交互方案，待确认  
> 适用项目：Local ERP Production Flow Suite  
> 本阶段范围：信息架构、角色入口、页面结构、任务流、交互规则与实施路线  
> 本阶段不包含：代码修改、数据库修改、RBAC 修复、业务台账修复

---

## 1. 执行摘要

当前 ERP 的问题不是单纯“页面不好看”，而是系统以功能和开发模块为中心组织页面，没有以用户每天要完成的任务为中心组织页面。

用户登录后同时面对十几个一级菜单、十几个经营指标、多个表单、台账、规则和历史记录，无法迅速判断：

1. 今天有什么事情必须处理；
2. 哪件事情最紧急；
3. 应该从哪里开始；
4. 当前单据处于哪一步；
5. 完成当前动作后下一步是什么。

本方案的核心目标是把 ERP 从“功能陈列式系统”改造成“角色任务式系统”。

设计北极星：

> 用户登录后 5 秒内知道“今天我要做什么”，并在 2 次点击内开始处理第一项任务。

目标操作路径统一为：

```text
登录
  ↓
我的工作台
  ↓
待办/异常队列
  ↓
单据详情
  ↓
唯一的下一步动作
  ↓
处理完成，返回队列
```

## 2. 现状与问题定义

### 2.1 当前运行时复杂度

本轮审计实际测量的典型页面高度如下：

| 页面 | 当前高度 | 主要问题 |
|---|---:|---|
| 经营总览 | 约 5,582px | 指标卡和经营信息挤占待办入口 |
| 生产执行 | 约 6,010px | 计划、执行、日报、领料、成本混排 |
| 采购仓储 | 约 12,382px | 采购、供应商、仓储、IQC、应付混在一页 |
| 审批算价 | 约 5,760px | 审批、算价、预警订阅互不相关 |
| 系统管理 | 约 69,075px | 系统、整改、冲销、参数、权限、日志混排 |

页面高度只是症状，根因是信息架构和任务模型错误。

### 2.2 四类结构性问题

#### 导航问题

- 大部分角色看到近乎相同的一级菜单；
- 菜单按系统功能划分，不按岗位任务划分；
- 模块名称不能帮助用户预测功能位置；
- 低频管理功能与高频业务功能处于同一层级。

#### 首页问题

- 首页先展示大量经营指标，而不是“我的待办”；
- 零值指标仍占据大量空间；
- 指标缺少优先级，没有区分待办、异常和经营结果；
- 操作人员与管理人员使用同一套首页。

#### 页面问题

- 页面按开发顺序向下堆叠；
- 表单、可操作台账、只读台账、规则配置和历史记录同时展开；
- 用户需要滚动寻找操作入口；
- 同一业务动作在多个页面重复出现。

#### 流程问题

- 用户只看到当前单据状态，看不到下一步动作；
- 表单和提交动作可能分离；
- 操作成功后缺少下一步引导；
- 同一个角色完成一个节点时可能需要跨多个模块。

## 3. 对现有两份方案的评价

现有文档：

- [ERP 页面结构重构方案](./ERP页面结构重构方案.md)
- [ERP 页面结构与导航重构方案](./ERP页面结构与导航重构方案.md)

其中以下结论应保留：

- 首屏指标控制在 4～6 个；
- 去掉重复标题；
- 消除静默截断；
- 表单和操作按钮就近；
- 每个业务动作只保留一个权威入口；
- 拆分采购仓储和系统管理；
- 修改密码移到用户菜单；
- 算价归入销售，IQC 归入质量，冲销归入财务。

以下部分需要升级：

1. 不应把 12 个平铺菜单直接增加到 14 个平铺菜单；
2. Tab 只能缩短页面，不能解决用户不知道该做什么；
3. 普通操作人员首页不应是纯只读驾驶舱，而应是任务工作台；
4. 页面长度不能作为唯一验收标准，必须以任务完成效率验收；
5. 系统应先区分角色，再决定导航、首页和快捷操作。

## 4. 产品设计原则

### 4.1 角色优先

用户只看到与本人职责和权限有关的功能。管理员可以访问全部能力，但完整导航默认分组折叠。

### 4.2 首屏即任务

普通用户首屏首先回答：

- 我今天有多少待办；
- 哪些已经超时；
- 哪些存在异常；
- 我可以立即执行什么动作。

### 4.3 一页一个主要目的

一个页面只能有一个主要任务。页面可以有多个辅助操作，但只能有一个视觉最强的主要按钮。

### 4.4 一项业务一个权威入口

同一动作不允许出现在多个模块中。例如：

- 收款只在财务执行；
- 付款只在财务执行；
- IQC 判定只在质量执行；
- 到货签收只在仓库执行；
- 发料只在仓库执行；
- 配方算价只在销售报价上下文执行。

其他模块只显示结果、状态和跳转入口。

### 4.5 渐进展示

复杂度按照四层逐步展开：

```text
第一层：角色导航，只显示 4～6 个日常入口
第二层：任务队列，显示今天要处理的事情
第三层：单据详情，展示业务上下文和流程状态
第四层：抽屉或弹窗，执行具体业务动作
```

规则、历史、附件、日志和系统配置不抢占第一层和第二层。

### 4.6 状态必须可行动

任何业务状态必须同时回答：

1. 当前处于哪一步；
2. 为什么停在这里；
3. 谁应该处理；
4. 下一步可以执行什么；
5. 超过期限后会发生什么。

## 5. 目标信息架构

### 5.1 完整能力导航

```text
我的工作台

业务运营
  ├─ 销售管理
  ├─ 生产管理
  └─ 质量管理

供应链
  ├─ 采购管理
  ├─ 库存仓储
  └─ 供应商管理

财务与分析
  ├─ 应收应付
  ├─ 报表中心
  └─ 预警与整改

基础与协作
  ├─ 主数据
  ├─ 审批中心
  └─ 档案中心

系统管理
  ├─ 账号与权限
  ├─ 系统参数
  └─ 审计日志
```

### 5.2 不再作为普通一级菜单的功能

| 当前功能 | 目标位置 |
|---|---|
| 经营总览 | 区分“我的工作台”和“管理驾驶舱” |
| 流程驾驶舱 | 管理驾驶舱中的流程监控页 |
| 审批算价 | 算价归销售；审批归审批中心 |
| 本地归档 | 改名档案中心，进入基础与协作分组 |
| 系统管理 | 仅管理员可见 |
| 平行账套 | 管理员专用独立工作区或功能开关 |
| 单据作废、冲销、红冲 | 财务与异常处理 |
| 上线自检 | 系统初始化阶段使用，上线后默认隐藏 |

## 6. 角色导航方案

系统当前包含 `sales`、`assistant`、`production`、`warehouse`、`purchasing`、`quality`、`technical`、`manager`、`finance`、`admin` 等角色。目标导航建议如下。

| 角色 | 默认首页 | 默认可见入口 |
|---|---|---|
| 商务销售 `sales` | 销售工作台 | 销售管理、客户、我的审批、销售报表 |
| 商务助理 `assistant` | 交付工作台 | 订单交付、发货退货、客户、我的审批 |
| 生产 `production` | 生产工作台 | 生产计划、生产执行、物料需求、生产报表 |
| 仓库 `warehouse` | 仓库工作台 | 收货、发料、库存、盘点 |
| 采购 `purchasing` | 采购工作台 | 采购管理、供应商、到货跟踪、库存查询 |
| 质量 `quality` | 质量工作台 | IQC、成品检验、质量处置、质量台账 |
| 技术 `technical` | 技术处置工作台 | 技术处置、BOM查询、质量异常、变更待办 |
| 管理者 `manager` | 管理驾驶舱 | 经营概览、流程监控、异常中心、审批、报表 |
| 财务 `finance` | 财务工作台 | 应收、应付、收付款、冲销对账 |
| 管理员 `admin` | 系统管理工作台 | 完整能力导航，按分组折叠 |

规则：

- 普通角色默认一级入口不超过 6 个；
- 无操作权限的模块不显示在主导航；
- 只读查询通过详情页链接、全局搜索或“更多”入口访问；
- 一个用户拥有多个角色时，工作台合并任务，不重复展示菜单；
- 用户可切换岗位视图，但不因此获得额外数据权限。

## 7. “我的工作台”设计

### 7.1 普通操作人员工作台

```text
┌──────────────────────────────────────────────┐
│ 上午好，张经理                               │
│ 今天有 5 项待办，其中 1 项已经超时            │
│ [新建报价] [发起采购] [登记到货]              │
├────────────────────────┬─────────────────────┤
│ 我的待办                │ 异常与风险           │
│ 2 张报价待确认          │ 1 张订单交期风险      │
│ 1 张采购申请待审批      │ 2 项低库存            │
│ 1 批原料待 IQC          │ 1 笔应收逾期          │
│ 1 笔回款待登记          │                      │
├────────────────────────┼─────────────────────┤
│ 最近处理                │ 业务摘要             │
│ 最近打开的 5 张单据      │ 订单/库存/应收/生产    │
└────────────────────────┴─────────────────────┘
```

### 7.2 管理人员驾驶舱

管理人员首页与普通工作台不同，重点回答：

- 哪些业务节点阻塞；
- 哪些订单可能延期；
- 哪些异常影响金额最大；
- 哪些审批等待时间最长；
- 经营趋势是否偏离目标。

管理驾驶舱允许展示趋势图和经营指标，但仍需把异常和待决策事项放在首屏。

### 7.3 工作台显示规则

- 待办最多显示 6 项；
- 异常最多显示 5 项；
- KPI 最多显示 4 个；
- 零值指标不默认展示；
- 每项待办必须可以点击进入对应单据；
- 快捷操作根据角色、权限和当前状态生成；
- 不在首页展示完整台账、完整日志和大段表单；
- “查看全部”进入对应任务中心，不在首页无限展开。

## 8. 全局页面框架

### 8.1 左侧导航

- 显示当前角色需要的模块；
- 分组可折叠；
- 显示待办数量，不显示无意义总数量；
- 当前模块清晰高亮；
- 管理员完整导航默认折叠；
- 平行账套不与正式账套功能混排。

### 8.2 顶部栏

顶部只保留：

- 全局搜索；
- 快速新建；
- 我的通知；
- 当前账套/环境标识；
- 当前用户与角色；
- 修改密码和退出登录。

删除顶部与左侧导航重复的模块名称和说明。

### 8.3 全局搜索

搜索结果按实体分组：

```text
订单：DD-20260821-001
报价：BJ-20260820-003
客户：上海星河装备有限公司
物料：M-STEEL-001
采购单：CG-20260819-002
生产单：SC-20260818-001
```

搜索结果必须遵循数据权限，只展示用户可以访问的实体。

## 9. 统一业务页面模板

### 9.1 列表页

```text
模块名称 / 当前待办数                         [主要操作]

[待处理] [全部单据] [异常] [统计]

筛选：状态、日期、业务对象、负责人     [保存视图]

单据列表
──────────────────────────────────────────────
单号    业务对象    金额/数量    当前状态    下一步
DD001   客户 A      ¥12,000      待确认      [确认订单]
DD002   客户 B      ¥8,000       待排产      [查看详情]
```

规则：

- 默认进入“待处理”，不是“全部历史数据”；
- 主要操作按钮最多一个；
- 列表必须有总数、搜索、筛选和分页；
- 行内只展示最常用动作，其余放入“更多”；
- 异常、超时、被驳回必须明确显示原因；
- 用户可以保存个人筛选视图。

### 9.2 单据详情页

```text
返回待办列表

订单 DD001                         状态：待确认
客户 A / ¥12,000 / 交期 9 月 1 日  [确认订单]

[基本信息] [明细] [流程记录] [相关单据] [附件]

流程：
报价完成 → 当前：订单确认 → 待排产 → 待生产 → 待发货

下一步说明：
确认客户交期、合同号和收货信息后转为正式订单。
```

详情页必须包含：

- 单据编号和当前状态；
- 业务对象和关键金额/数量；
- 当前责任人；
- 流程进度；
- 下一步动作；
- 明细行；
- 相关上下游单据；
- 附件；
- 操作时间线和审计记录。

### 9.3 动作抽屉或弹窗

适用于确认、审批、收货、质检、发料、付款等有明确上下文的动作。

```text
确认订单 DD001

客户：客户 A
金额：¥12,000

交付日期  [________]
客户 PO   [________]
合同号    [________]
收货信息  [________]

[取消]                         [确认转订单]
```

规则：

- 表单与提交按钮必须处于同一视觉区域；
- 抽屉标题必须说明正在操作哪张单据；
- 不允许没有上下文的通用收款、付款、入库表单；
- 高风险动作必须展示影响范围；
- 成功后告诉用户结果和下一步，而不是只弹“操作成功”。

## 10. 核心模块重构方案

### 10.1 销售管理

目标二级结构：

```text
待处理
报价单
销售订单
发货与退货
销售对账
```

主要调整：

- 默认展示待确认报价、待转订单、待发货和交期风险；
- “新建报价”作为主要操作；
- “正式订单录入项”从常驻表单改为报价转订单时的确认抽屉；
- 配方价格试算归入报价上下文；
- 应收只读摘要保留，收款跳财务；
- 发货和退货围绕订单详情处理，不再展示多组孤立表单。

### 10.2 生产管理

目标二级结构：

```text
生产任务
计划与排程
执行与日报
领料与补退料
生产成本
```

主要调整：

- 默认展示待排产、待领料、生产中、待报工和异常工单；
- 减少首屏指标，只保留延期、停滞、缺料、异常；
- 计划、执行、日报和成本使用独立视图；
- 仓库发料动作移到库存仓储；
- 生产侧只查看领料状态和批次结果；
- 每张生产单展示流程、计划进度、实际进度和下一步动作。

### 10.3 采购管理

目标二级结构：

```text
采购待办
MRP 建议
采购申请
采购订单
合同与到货
```

主要调整：

- 默认展示待转采购、待下单、待到货和到货差异；
- 采购申请、采购单、合同和到货建立上下游关系；
- 到货签收只在仓库执行；
- IQC 结果只读，质量判定跳质量管理；
- 应付只显示状态，付款跳财务；
- 供应商治理从采购页面拆出。

### 10.4 库存仓储

目标二级结构：

```text
今日作业
收货
发料
当前库存
批次追溯
盘点与调整
呆滞库存
```

主要调整：

- 仓库工作台首先展示今天要收、要发、要盘的任务；
- 仓库发料操作台从生产模块迁入；
- 到货签收从采购模块迁入；
- 盘点、调整、批次追溯分别建立队列和详情；
- 当前库存默认列表化，不以大量指标卡展示；
- 低库存、积压和批次异常进入异常队列。

### 10.5 质量管理

目标二级结构：

```text
待检任务
原料 IQC
成品检验
技术处置
质量台账
```

主要调整：

- 默认首页就是待检队列；
- IQC 发起、判定和记录集中在质量模块；
- 采购只跟踪到货和检验状态；
- 完工请验、检验结果、技术处置和成品入库建立流程关系；
- 不合格、待复检、待技术处置作为独立异常队列；
- 成品入库动作由有权限的仓库角色执行或明确交接。

### 10.6 财务管理

目标二级结构：

```text
财务待办
应收
应付
收款
付款
退款与冲销
```

主要调整：

- 默认展示逾期应收、待确认回款、到期应付和待复核冲销；
- 选中一笔应收后才能登记收款；
- 选中一笔应付后才能登记付款；
- 退款、冲销、红冲和单据作废集中到异常处理；
- 财务操作必须展示原始单据和影响金额；
- 销售和采购模块只显示财务状态，不提供资金操作。

### 10.7 供应商管理

目标二级结构：

```text
供应商台账
资质证书
准入与限制
绩效与复评
整改与观察期
```

主要调整：

- 供应商基础资料与采购执行分离；
- 供应商详情页集中展示基础资料、资质、绩效、订单、差异和整改；
- 默认展示资质临期、准入限制和待整改供应商；
- 规则配置仅管理员可见；
- 大量只读历史台账放入供应商详情，不在首页全部展开。

### 10.8 主数据

目标二级结构：

```text
客户
供应商基础资料
物料
产品
BOM
导入与初始化
```

主要调整：

- 正式上线初始化向导默认隐藏，仅初始化阶段开放；
- BOM 导入只保留一个权威入口；
- 主档使用统一列表和详情模板；
- 新建和编辑采用抽屉；
- 停用、版本、历史变更进入详情页。

### 10.9 审批中心

目标二级结构：

```text
我的待审批
我发起的
审批历史
审批规则（管理员）
```

主要调整：

- 配方算价移出审批中心；
- 预警订阅移出审批中心；
- 普通用户看待审批和已发起；
- 管理员才看到规则和模板；
- 审批详情必须展示来源业务单据和影响范围。

### 10.10 预警与整改中心

目标二级结构：

```text
我的异常
经营预警
成本异常
整改任务
规则与订阅（管理员）
```

主要调整：

- 合并散落在总览、报表、审批和系统管理中的预警入口；
- 普通用户只看到与本人相关的异常和整改；
- 规则配置默认隐藏；
- 异常详情展示来源单据、影响金额、责任人、期限和整改记录；
- 管理员首页只显示异常摘要，不展开全部整改台账。

### 10.11 系统管理

目标二级结构：

```text
账号与角色
权限矩阵
系统参数
单据编号
登录与审计日志
数据维护
```

主要调整：

- 仅管理员可见；
- 修改本人密码移到全局用户菜单；
- 冲销、红冲和作废移到财务；
- 上线整改移到预警与整改中心；
- 账号、权限、参数和日志使用独立页面，不再纵向堆叠；
- 危险的数据维护动作单独放置并明确标识。

## 11. 功能分级与显隐规则

### A 级：日常高频任务

示例：订单确认、排产、收货、发料、质检、收款、付款。

处理方式：

- 出现在角色导航；
- 出现在工作台待办；
- 可以通过快捷操作进入；
- 默认展示待处理队列。

### B 级：周期性业务

示例：盘点、供应商复评、报表导出、成本分析、退货处理。

处理方式：

- 放在模块二级导航；
- 有待办时可以进入工作台；
- 无待办时不抢占首屏。

### C 级：低频管理和配置

示例：规则配置、期初初始化、系统参数、平行账套、正式上线自检。

处理方式：

- 仅特定角色可见；
- 放在设置或高级功能；
- 默认折叠；
- 不进入普通用户工作台。

## 12. 全局交互规则

### 12.1 指标规则

- 每页首屏最多 4～6 个指标；
- 只展示与当前任务相关的待办、异常和风险指标；
- 零值指标默认隐藏；
- 总数量放在列表标题或次级统计页；
- 所有指标可点击并落到对应筛选后的列表。

### 12.2 表格规则

- 所有表格必须显示总数；
- 必须支持搜索、筛选、排序和分页；
- 禁止无提示的 `slice(0, N)`；
- 只读历史表默认折叠或放入详情页；
- 列表默认展示用户真正需要决策的列；
- 状态、责任人和下一步动作必须可见。

### 12.3 表单规则

- 表单和提交按钮不能分离；
- 新建使用独立页或抽屉；
- 行为依赖某张单据时，从单据详情发起；
- 默认值必须来自业务规则，不能保留演示数据；
- 表单离开前提示未保存内容；
- 高风险动作展示影响摘要并要求确认。

### 12.4 状态与颜色

- 蓝色：当前可执行；
- 黄色：等待、关注、即将超时；
- 红色：异常、阻断、已超时；
- 绿色：完成；
- 灰色：未开始、无权限或不适用。

颜色必须配合文字和图标使用，不能只依赖颜色表达状态。

### 12.5 成功反馈

禁止只显示“操作成功”。标准成功反馈应为：

```text
订单 DD001 已确认。
下一步：等待生产计划员排产。

[返回待办] [查看订单详情]
```

## 13. 典型角色流程示例

### 13.1 销售确认订单

```text
销售登录
  → 工作台显示“2 张报价待确认”
  → 点击报价 BJ001
  → 详情显示当前状态“客户已确认”
  → 主要按钮“转为正式订单”
  → 抽屉补充交期、PO、合同和收货信息
  → 确认
  → 系统提示“订单已创建，下一步等待排产”
```

### 13.2 仓库发料

```text
仓库登录
  → 工作台显示“3 张领料单待发料”
  → 点击领料单 LL001
  → 查看物料、批次建议和库存
  → 选择实际批次
  → 主要按钮“确认发料”
  → 系统提示库存变化和生产单状态
```

### 13.3 质量完成 IQC

```text
质量登录
  → 工作台显示“1 批原料待检”
  → 点击 IQC 单
  → 查看采购、到货、供应商和抽样信息
  → 录入检验结果
  → 选择合格/不合格/让步处置
  → 系统提示后续入库或技术处置
```

### 13.4 财务登记回款

```text
财务登录
  → 工作台显示“1 笔回款待确认”
  → 进入应收单
  → 查看客户、订单、发货和历史回款
  → 主要按钮“登记回款”
  → 录入金额、日期、方式和凭证
  → 系统提示剩余应收和下一步
```

## 16. 验收标准

### 16.1 导航与认知

- 登录后 5 秒内能说出自己有多少待办；
- 普通角色默认一级入口不超过 6 个；
- 新用户一次猜对 80% 以上功能位置；
- 管理员完整导航分组折叠，不再平铺；
- 普通用户看不到与本人无关的系统配置入口。

### 16.2 任务效率

- 日常第一项任务不超过 2 次点击；
- 一个角色完成自己的业务节点不跨多个模块；
- 80% 以上高频任务从工作台直接进入；
- 操作完成后明确提示结果和下一步；
- 典型任务首次使用完成率不低于 80%。

### 16.3 页面结构

- 首页 KPI 不超过 4 个；
- 首页待办不超过 6 项；
- 任一页面只有一个主要操作；
- 默认打开待处理列表，不默认展开所有历史数据；
- 无静默截断；
- 所有列表有搜索、筛选、分页和总数；
- 表单与提交按钮分离数量为 0。

### 16.4 入口一致性

- 每个业务动作只有一个权威操作入口；
- 其他模块只提供状态、摘要和跳转；
- 附件能力统一；
- 审计能力统一；
- 收付款、IQC、到货签收和发料不再重复出现。

### 16.5 用户测试建议

每类角色至少选择 3 个真实任务：

| 角色 | 建议测试任务 |
|---|---|
| 销售 | 新建报价、转正式订单、查看交付状态 |
| 生产 | 排产、创建日报、处理补退料 |
| 采购 | 处理 MRP 建议、生成采购单、跟踪到货 |
| 仓库 | 到货签收、发料、盘点 |
| 质量 | 完成 IQC、成品检验、技术处置 |
| 财务 | 登记回款、登记付款、查看逾期 |
| 管理者 | 审批、发现阻塞、处理异常 |
| 管理员 | 新建用户、调整权限、查询审计日志 |

记录以下指标：

- 是否成功完成；
- 完成时间；
- 点击次数；
- 是否走错模块；
- 是否需要他人指导；
- 用户认为下一步是否清晰。

## 17. 风险与应对

| 风险 | 应对 |
|---|---|
| 老用户找不到原入口 | 新旧位置提示保留 2～4 周，提供迁移对照表 |
| 一次性改动过大 | 按角色和模块分批上线，可独立回滚 |
| 只缩短页面但任务仍不清楚 | 使用真实任务测试，不以页面高度单独验收 |
| Tab 数量继续膨胀 | 每个模块二级导航建议不超过 7 项，低频功能进入更多/设置 |
| 权限和导航不一致 | 导航、数据范围、动作权限使用同一角色能力定义 |
| 全局搜索暴露数据 | 搜索结果必须经过数据权限过滤 |
| 管理员仍然信息过载 | 完整能力按业务域分组折叠，首页仍以系统待办为主 |

## 18. 本方案明确不做的事情

本阶段不建议：

- 先整体换颜色、图标、字体和圆角；
- 只使用 Tab 把长页面藏起来；
- 在现有结构上继续增加一级菜单；
- 在完成任务架构前拆分全部前端代码；
- 把所有功能同时重做；
- 把平行账套和主界面重构一起上线；
- 用页面高度代替用户任务验收。

当前视觉语言可以暂时保留。第一优先级是角色入口、任务队列、单据详情和下一步动作。

## 19. 下一步需要确认的产品决策

进入原型阶段前，需要确认：

1. 一个用户是否允许绑定多个角色；
2. 各岗位每天最高频的 5 个任务；
3. 管理者是否需要独立经营驾驶舱；
4. 销售、采购、仓库、质量、财务之间的正式职责边界；
5. 哪些业务动作允许跨角色代理处理；
6. 哪些功能属于所有客户必备，哪些属于高级功能；
7. 平行账套是否需要继续作为产品能力；
8. 正式上线后是否隐藏初始化、自检和演示功能。

这些问题不会阻塞本方案成立，但会影响最终的角色菜单和工作台内容。

## 20. 最终结论

本次重构不应被定义为“页面美化”，而应定义为：

> 以角色、待办、单据和下一步动作为核心的 ERP 任务体验重构。

成功后的系统不要求用户记住全部功能在哪里。系统应该根据用户身份和单据状态，主动告诉用户：

- 你现在需要处理什么；
- 为什么需要处理；
- 从哪里开始；
- 操作会影响什么；
- 完成后下一步是什么。

这才是解决“进入 ERP 后完全懵”的根本方案。
